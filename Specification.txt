IN2011 Computer Networks: Coursework 1 (65%)
Deadline: Monday May 1st 2026, 17:00
This coursework assesses your ability to use what you have learnt about networking to
build functioning software that interacts with network services. This includes the
following:
● Understanding the IP network layer and UDP transport layer.
● Being able to read and understand the specification of an application layer
protocol.
● Using Java to implement the application layer protocol.
● Use cryptographic hashes.
Because this is a second year unit, we will assume that you have the following skills
from the first year:
● Can write Java programs that are hundreds of lines long.
● Be able to test your software so that it is robust against a range of inputs and
errors.
● Be able to build and run your software on a variety of different operating systems
and configurations.
● Understand what a hash table and a stack are and how they are used.
● Understand how a number or a string of bytes can be represented using
hexadecimal.
● Perform bit-wise comparisons on arrays of bytes.
You will not get marks for these but you need to know them to do this coursework. If you
do not feel confident about these please revise your notes from last year and talk to the
staff running your practical sessions or your personal tutor.

5.2. Testing Advice
● Test against lab network nodes.
● Also run multiple local Node instances for faster iteration.
● Use netcat to manually send UDP messages to understand protocol behaviour.
● Use sha256sum on lab machines to verify hash correctness.
○ Be careful with trailing newline characters.
● Simulate packet loss by randomly discarding packets (use fixed seed for
repeatability).
● Use Wireshark to confirm:
○ Messages are actually sent.
○ Transaction IDs match.
○ Retransmissions occur after ~5 seconds.
○ Responses go to the correct port.
5.3. Common Mistakes
Message Formatting
● Missing final trailing space.
● Incorrect CRN string encoding.
● Off-by-one parsing errors.
● Mishandling empty strings.
● Assuming values contain no spaces.
Transaction IDs
● Including spaces in txid.
● Generating duplicate txids.
● Not copying requests into response.
● Assuming responses arrive in order.
6
Hashing & Distance
● Hashing wrong input.
● Incorrect hex formatting.
● Comparing hex characters instead of bits.
● Using incorrect distance formula.
Storage Rules
● Ignoring the “3 per distance” rule.
● Accepting writes when three strictly closer nodes exist.
● Failing to rebalance data.
● Not removing broken nodes.
Relay
● Forwarding request but not returning response.
● Using wrong transaction ID in relay response.
● Blocking while processing relay.
Compare-and-Swap
● Not atomic.
● Swapping requested/new values.
● Returning incorrect response codes.
● Modifying value when compare fails.
5.4. Debugging Strategy
● Log every received and sent message.
● Make spaces visible when debugging formatting issues.
● Test pure functions separately:
○ String encode/decode.
○ SHA-256.
○ Distance calculation.
● Reduce complexity if stuck, disable advanced features and reintroduce gradually.
● If the tester reports “no response”:
○ Check you sent one.
○ Check the correct port/address.
○ Check exact formatting.
